# rosduino_gen

[Русский](README_RU.md)

**C++ headers for a RosDuino sketch, generated from ROS 2 `.msg` and `.srv` files.** The [Arduino library](https://github.com/rosduino/rosduino_arduino) already contains the common types. This package writes headers for the rest, and it can regenerate that common set.

```bash
ros2 run rosduino_gen rosduino-gen --package my_robot_msgs --out "$HOME/Arduino/libraries/RosDuino/src"
```

The repository overview is [../README.md](../README.md). The program that talks to the board is [`rosduino_agent`](../rosduino_agent/README.md).

## Build

From the repository root, with ROS 2 sourced:

```bash
source /opt/ros/$ROS_DISTRO/setup.bash
colcon build --packages-select rosduino_gen
source install/setup.bash
```

ROS 2 **Lyrical** is the distribution this generator runs in.

## Generate

```bash
ros2 run rosduino_gen rosduino-gen --list
ros2 run rosduino_gen rosduino-gen --list --package std_msgs
ros2 run rosduino_gen rosduino-gen --package std_msgs
ros2 run rosduino_gen rosduino-gen --package std_msgs --package sensor_msgs
ros2 run rosduino_gen rosduino-gen --all
```

Headers go to `generated/` in this package unless you pass `--out`.

| Flag | Effect |
|---|---|
| `--list` | Print interface names (`pkg/msg/Name`, `pkg/srv/Name`) and exit. Without `--package`, print every interface ROS 2 knows |
| `--package PKG` | Generate one package. Repeat the flag for several packages |
| `--all` | Clear the output directory, then generate the types in [`arduino_types.txt`](arduino_types.txt). Nested types are added on their own |
| `--out DIR` | Output directory. The default is `generated/` in this package |
| `--default-seq-cap N` | Capacity of an unbounded array `T[]` (default 8) |
| `--parser auto\|simple\|rosidl` | Parser. `auto` uses the ROS 2 parser when it is installed |

`--all` together with `--package` is an error. Pass one of `--package`, `--all`, or `--list`.

## Put the headers in the library

A generated `.h` is not on the board until it sits in the Arduino library, next to `rosduino/`, with the layout `pkg/msg/Name.h` or `pkg/srv/Name.h`.

| OS | Library sources |
|---|---|
| Linux | `~/Arduino/libraries/RosDuino/src/` |
| macOS | `~/Documents/Arduino/libraries/RosDuino/src/` |
| Windows | `Documents\Arduino\libraries\RosDuino\src\` |

`--out` can point straight at that `src/` directory. A sketch includes the type the ROS 2 way. The short name drops `msg` and `srv`:

```cpp
#include <my_robot_msgs/msg/Status.h>

my_robot_msgs::Status status;   // or my_robot_msgs::msg::Status
```

## The bundled set

[`arduino_types.txt`](arduino_types.txt) is the list `--all` writes. A line is a whole package or one type (`pkg/msg/Name`, `pkg/srv/Name`). Nested types of a listed type are written too. `--all` clears the output directory first, so a file that is not part of that list does not remain.

To add your own types to that set, append them to `arduino_types.txt` and run `--all` again.

The Arduino library ships the result of that list: `builtin_interfaces`, `std_msgs`, `std_srvs`, `example_interfaces`, and selected `geometry_msgs`, `sensor_msgs`, and `nav_msgs` types.

## What a header contains

The first lines are `Generated by rosduino-gen. Do not edit.`, then the name `pkg/msg/Name` or `pkg/srv/Name`, then the full source `.msg` or `.srv` as `//` comments: fields, constants, `#` comments, and the `---` of a service. Nested types are not pasted into that comment.

The RIHS01 hash comes from `share/<pkg>/msg/<Type>.json` or `share/<pkg>/srv/<Type>.json`. If that file is missing, the header stores `0` and the generator prints a warning on stderr.

These headers are C++11, with no heap and no STL, so they compile on Nano, Uno, Micro, Mega, and Due. They are a different file from the `.hpp` headers `rosidl_generator_cpp` writes for a Linux node. The field-by-field comparison is in Russian: [doc/arduino_due.md](doc/arduino_due.md).

A service is one struct with `request` and `response`:

```cpp
#include <std_srvs/srv/SetBool.h>

std_srvs::SetBool srv;
srv.request.data = true;
```
